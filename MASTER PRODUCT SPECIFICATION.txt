2. CLIENT

For V1:

One client/company = one login.

There is no public registration.

Admin creates the account.

Example:

Client
Kura Homes

Email:
marketing@kurahomes.in

Password:
generated by admin

Client logs in and sees:

ONLY Kura Homes data.

They cannot:

access another client's calendar
query another client's content
guess another client's URL
access another client's notifications
access another client's files
access another client's activity

This must be enforced at the server/database authorization level, not just by hiding things in the frontend.

10. IMPORTANT — CLIENT EDITING + APPROVAL

Because you've chosen:

Client can edit caption directly.

I recommend this workflow:

READY FOR REVIEW
       ↓
CLIENT REVIEWS
       ↓
CLIENT EDITS CAPTION
       ↓
SAVE CHANGES
       ↓
CLIENT APPROVES

The system should retain the previous caption in activity history.

If a client edits an already-approved caption, we should not silently change an approved record.

Instead:

APPROVED
   ↓
CLIENT EDITS
   ↓
CHANGES MADE AFTER APPROVAL
   ↓
REQUIRES RE-APPROVAL

That is important operationally.

19. SECURITY

This is one of the most important parts of the prompt.

Do NOT rely on:

if client then hide other clients

in React.

Instead:

Request
   ↓
Authentication
   ↓
Identify User
   ↓
Identify Client/Tenant
   ↓
Authorization
   ↓
Database query scoped to tenant
   ↓
Return data

Example:

Client A requesting:

/content/123

must not be able to see Content 123 if Content 123 belongs to Client B.

Even if they manually modify URLs/API requests.

20. UI DIRECTION

From the screenshot you provided, I would take inspiration from:

premium SaaS aesthetic
lots of whitespace
elegant typography
subtle borders
restrained shadows
rounded cards
muted background
clean navigation
small status indicators
strong typography hierarchy

But do not copy the screenshot.

Our application should feel like:

Linear + Notion + modern premium client portal

rather than a generic Bootstrap dashboard.

Avoid:

huge colorful dashboards
excessive gradients
excessive glassmorphism
giant cards
unnecessary animations
dashboard charts that don't provide value

The calendar and content itself should be the hero.
